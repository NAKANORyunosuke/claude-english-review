# 序文・主定理点検エージェント プロンプト雛形

Abstract・Introduction・主定理の専用点検。分割せず、1エージェントが1文ずつ読む。
本文の分割点検(`r-check-chunk.md`)より**先**に回す(`PLAYBOOK.md` フェーズ0)。

置換変数: {{RULES}} 執筆規則 / {{NOTATION}} 記法規則 / {{LEDGER}} 記号台帳(無ければ「なし」) / {{TEX}} 対象 tex / {{RANGE}} 序文の行範囲 / {{OUT}} 出力ファイル / {{TERMS}} 承認済み用語。

---

数学論文の序文と主定理の点検タスク。編集はせず、指摘のみをファイルに書く。
序文は逐語で書き直される部分なので、本文点検より細かく見る。

## 手順
1. {{RULES}} と {{NOTATION}} を全文読む。{{LEDGER}} があれば読む。
2. {{TEX}} の {{RANGE}} を Read で読む。
3. 序文に現れる記号を**全数列挙**し、定義位置を確認する(下記「記号表」)。
4. 下記の10観点で1文ずつ点検する。
5. 確信のない指摘は出さない。

## 観点

1. **前方参照ゼロ**: `see Section~\ref{...} for the definition(s) of ...` を序文に書かない。序文で使う記号は序文で定義しきる。証明の詳細への参照は可。
2. **定義の完備性**: 序文の記号で定義が序文内に無いものは、書き下す案を出す。行列・群・写像は名前で呼ぶだけにせず、実体を書く。
3. **定義と正規化の分離**: 「空間の定義」と「代表元の完全系」を1文に混ぜない。2段に割る。
4. **1文1機能**: 定義・正規化・説明を1文に詰めない。詰まっていれば分割案を出す。
5. **主張の一意性**: 主定理は1回だけ述べる。序文で述べたら本文で再掲しない(`\label` は序文側に置く)。同じ主張・同じ定義が2箇所にあれば指摘する。
6. **定理環境の中身**: 定理には仮定と主張だけ。正規化・分岐の選択・凸性などの設定文が入っていれば、地の文へ移す案を出す。
7. **声**: 自分の結果は "We ..."、先行研究は受動態。Abstract で先行研究の人名を主語にしない。
8. **引用の粒度**: ページ範囲(`pp.~120--136`)ではなく番号付きの結果(`Proposition 3.6`)で引く。
9. **削る文**: 既出の等式を言い換えるだけの文、自分の正規化の意義を述べる文は削る。
10. **長い主語**: 動詞まで8語を超える主語({{RULES}} 1.11)。仮主語・受動態・`we` 主語での短縮案を出す。

## 出力
{{OUT}} に Write で書く。

```
## 裁定表
状態は 未処理 / 対応済(コミット) / 棄却 / 保留。適用のたびに同じコミットで更新する。

| 件 | 状態 | 内容 | 判断 |
| --- | --- | --- | --- |
| F1 | 未処理 | <1行で> | |

## 記号表
| 記号 | 意味 | 序文内の定義位置 | 判定 |
| --- | --- | --- | --- |
| \(U\) | ... | L120 | 定義あり |
| \(\Gamma_M\) | ... | なし(§2 を前方参照) | **要書き下し** |

## F<番号> <観点> L<行番号> — 未処理
現: <その行の全文をそのまま>
問題: <1行で。観点番号を付ける>
案: <置換後の行全文。分割するなら2行以上で。\ref/\eqref/\cite/数式を落とさない>

## 記号の決定案
<台帳へ確定すべき記号の変更。変更前・変更後・理由>
```

指摘には通し番号 `F<n>` を振る。裁定表と見出しの両方に状態を書き、適用時に**両方**を更新する(`PLAYBOOK.md` 報告書の状態欄)。

指摘ゼロなら記号表だけを書き、本文に `CLEAN` と書く。論文ファイルを編集しない。
最終応答は「<件数>件を <ファイル名> に出力」の1行でよい。
